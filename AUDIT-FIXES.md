## Acceptance status

Audit acceptance criteria 1 through 9 have code changes and local tests. Criterion 10, a live user-installed provider streaming session, is **not completed here**. The package includes a focused checklist below. It would be dishonest to label local simulated host tests as a live Gemini test.

After installing on a disposable chat: generate one normal streamed reply, stop another halfway through, simulate or encounter a provider error, generate a new swipe, and regenerate after the host removes its old reply. Confirm that only matching completed generations get verified-completion status. Verify Off overrides under Autopilot and inspect the sampled preview. Do not deliberately disrupt an important active chat to test failure handling.

## Boundaries retained deliberately

The detector does not infer all equivalent story beats, inspect hidden model reasoning, or prove authorial quality. Primarily English grammar and a finite known-activity vocabulary are used. Weak evidence is withheld from instructions. Provider/proxy transformations after the observed request event cannot be certified. Imported partial messages without recognizable metadata may be indistinguishable from legitimate saved text, but they are not used to invent a new learned generation association.

The response-checking system can verify host mechanics, not model obedience. Context sampling remains bounded and lexical rather than a complete world-state engine. No extra LLM or configuration forest was added.
